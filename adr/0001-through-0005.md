# Architectural decision records

## ADR-0001 — Network frontend, not embedded server

**Decision:** Bun/TS OpenTUI/Solid + `@opencode/client` connecting to shared OpenCode v2 service. **Rejected:** forking OpenCode core or embedding `@opencode/sdk`. **Reason:** running sessions survive UI closure, multiple clients reattach, server remains authoritative. [Client docs](https://opencode.ai/docs/build/client), [embedded SDK docs](https://opencode.ai/docs/build/sdk).

## ADR-0002 — Conversation and overview, not a terminal manager

**Decision:** only `overview` and `conversation(sessionID)` routes; no header bar, tabs, split panes, or embedded PTY. Left from empty composer moves to overview; running sessions continue. **Rejected:** full OpenCode TUI layout, tmux-like session windows. **Reason:** allow terminal emulator and shell to own window management. [Claude sessions](https://code.claude.com/docs/en/sessions); [OpenCode app](https://github.com/anomalyco/opencode/blob/v2.3.0/packages/tui/src/app.tsx).

## ADR-0003 — Keyboard-first, no chords; Shift+Tab is agent switching

**Decision:** single key/modifier per action, contextual precedence, `Shift+Tab` cycles server agents from `build`; `Ctrl+O` details; `Alt+P` models, Left overview. **Rejected:** Emacs-style `Ctrl+X` command prefixes; Claude's Shift+Tab permission mode. **Reason:** reliable tired-user muscle memory and direct access to OpenCode's agent feature. [OpenCode keys](https://opencode.ai/docs/cli/keybinds), [Claude keys](https://code.claude.com/docs/en/interactive-mode).

## ADR-0004 — Canonical transcript, derived folding

**Decision:** render from projected session messages and fold tool activities deterministically. Reasoning shown only when returned. **Rejected:** store sole conversation history as SSE events or client-generated summary text. **Reason:** reconnect, correctness, error visibility and no hallucinated reasoning. [OpenCode API](https://opencode.ai/docs/api), [projection source](https://github.com/anomalyco/opencode/blob/v2.3.0/packages/core/src/session/message-updater.ts).

## ADR-0005 — Explicit local plans with opt-in server instruction sync

**Decision:** versioned plan/goal sidecar with user-controlled sync into experimental instruction entry; never auto-mark tasks based on ordinary assistant text. **Rejected:** assuming OpenCode's existing session message history is itself a structured plan store. **Reason:** predictable task progress, multi-client conflict handling and future migration. [OpenCode instructions](https://opencode.ai/docs/api).
